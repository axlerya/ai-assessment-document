# ai-worker

Второй сервис системы понимания документов. Получает события об обработанных
документах, строит embeddings, индексирует чанки в pgvector, выполняет
гибридный поиск и reranking, собирает контекст и генерирует обоснованный
черновик, каждое утверждение которого подтверждено ссылкой на источник.

Границы ответственности заданы уставом [AGENTS.md](AGENTS.md). Сервис **не**
выполняет OCR и разбор PDF, **не** делит документы на чанки, **не** анализирует
правки оператора и **не** интерпретирует содержимое юридически: первое — работа
[`document-worker`](../document-worker), последнее — вне системы.

## Состояние

Собран скелет: каркас слоёв, обвязка проверок и ASGI-приложение с пробой
живости. Индексация, поиск и генерация появляются следующими этапами.

## Проверки

```bash
cd ai-worker
uv sync

uv run ruff check .            # линтер
uv run ruff format --check .   # формат
uv run mypy ai_worker tests    # типизация
uv run lint-imports            # границы слоёв
uv run deptry .                # лишние и необъявленные зависимости
uv run pytest                  # тесты
uv run pytest -m unit          # только без внешних зависимостей
```

Хуки репозитория ставятся один раз из его корня: `prek install`.

## Архитектура

Слои и правило зависимостей — Clean Architecture, направление внутрь:

```text
bootstrap → presentation | infrastructure → application → domain
```

Границы проверяются машинно, а не на ревью: семь контрактов `import-linter` в
[pyproject.toml](pyproject.toml) запрещают домену знать про фреймворки, а
application — про инфраструктуру, и отдельно запрещают импорт пакета соседнего
сервиса: результаты `document-worker` читаются из общей базы, а не импортом.
